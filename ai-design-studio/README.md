# AI Design Studio

Independent route: **http://localhost:5173/ai-design-studio**. The existing draw.io and React Flow tools retain their routes, source files, models, services and API behavior.

## Start

From the repository root:

```powershell
npm install
npm run build --workspace=@multi-agent/ai-design-studio
# First setup only; refuses to overwrite existing studio configuration.
npx tsx scripts/ai-design-studio-setup.ts
# Optional explicit index migration (Mongoose also creates these automatically).
npx tsx scripts/ai-design-studio-migrate.ts
npm run dev
```

MongoDB must be available at the application's existing `MONGODB_URL`. The root OpenAI configuration is reused, unchanged. Setup has already been run in this workspace. Read **`.env.ai-design-studio.credentials` locally** for the generated username/password. Restart the API after changing studio configuration. Do not commit credentials or environment files.

For a chosen account, set `STUDIO_SETUP_USERNAME` and `STUDIO_SETUP_PASSWORD` in the setup process environment before first setup. Passwords must have at least 12 characters. This avoids writing the generated credentials file. More accounts can be added to the JSON configuration using salted scrypt hashes generated by `passwordHash` in the studio authentication module. The same username is the ownership identity; rename accounts only with an explicit ownership migration.

## Configuration

| Variable | Purpose |
| --- | --- |
| `AI_DESIGN_STUDIO_USERS` | JSON object mapping username to `salt:scryptHash`; stored in the private studio environment file. |
| `AI_DESIGN_STUDIO_SESSION_SECRET` | HMAC session-signing secret, at least 32 characters in production. |
| `VITE_TLDRAW_LICENSE_KEY` | Public, domain-bound tldraw production license key. Set in the frontend build environment. This is **not** an OpenAI secret. |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | Existing server-side settings. This workspace uses `gpt-6-luna`; no model substitution is made. |
| `MONGODB_URL`, `PORT`, `CORS_ORIGIN` | Existing application settings. |

The additional server file `.env.ai-design-studio` is loaded without overriding existing environment variables. Production requires HTTPS, a configured session secret, authorized accounts, a valid tldraw production license, and a reverse proxy that serves the frontend and `/api` under the same origin. A process restart invalidates development sessions if no persistent signing secret is configured. Sessions expire after eight hours and are held in browser session storage.

Official references consulted: [tldraw licensing](https://tldraw.dev/community/license), [custom shapes](https://tldraw.dev/examples/custom-shape), [arrow bindings](https://tldraw.dev/examples/create-arrow), [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [OpenAI structured output](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat).

## Implemented behavior

Exactly seven semantic diagram types are supported: **Class, Sequence, Activity, Architecture (HLD), Use Case, State Machine, Deployment**. Whiteboard tools remain available in every diagram and are not another diagram type.

- `/ai-design-studio` is outside the dashboard layout. The application navigation returns when leaving this route. The compact toolbar, diagram tabs, collapsible assistant and Focus mode use the available viewport.
- Choose **Relevant diagrams (auto)** for one-prompt generation, or explicitly select one type. Review the generated diagram list and choose **Add diagram tabs**. Generated tabs share a system model with stable entity references. Existing diagrams are preserved. **Generate missing diagrams** restricts generation to absent types; **Regenerate selected diagram** proposes a new tab while retaining the original.
- Each tab stores its own semantic graph, canvas document/session snapshot, title and edit provenance. Switch, rename and duplicate tabs; duplicate whole projects using the header. New projects and legacy single-diagram documents use the version-2 workspace envelope. Existing documents migrate on read, without altering other collections.
- Custom class shapes show three compartments with visibility, parameters, return types, static underlining and abstract italics. Properties supports adding, removing and reordering members. Inheritance/realization have hollow triangles at the parent/interface; aggregation/composition have hollow/filled diamonds at the whole/source. Endpoint roles and multiplicities remain editable.
- Sequence diagrams use horizontal actors/participants, dashed lifelines, activation bars, ordered synchronous/asynchronous/return messages, and loop/alt/opt fragments. Edit message order in Properties; occupied orders are swapped atomically, and invalid return/fragment ordering is rejected. Edit fragment ranges, conditions and branch guards before reordering messages outside their original range.
- Activity diagrams use initial/final circles, actions, decision/merge diamonds, fork/join bars, guarded control flows and swimlanes. Use Case diagrams show actors, ellipses, system boundaries, include/extend and generalization. State diagrams show initial/final nodes, rounded states, composite states and event/guard transitions. Deployment diagrams show device/environment nodes, artifacts, deployment arrows and communication paths.
- The layout pipeline measures content before ELK hierarchical directed layout, routes orthogonal edges on an obstacle visibility grid, separates parallel connections, routes self-loops, places labels in free space and checks node/connector collisions. Sequence diagrams use a separate timeline. **Auto layout** explicitly repositions structured shapes; **Fit** adjusts only the viewport. Incremental operations preserve component coordinates and freehand drawings. The renderer uses editable semantic connector shapes with actual endpoint bindings. Bend/segment and label handles edit routing; endpoint selectors edit semantic connections.
- tldraw provides pan, zoom, pencil, eraser, editable text, sticky notes, shapes/arrows, selection, resizing, copy/paste, duplication, deletion, grouping, undo/redo, grid and snapping. Drawings remain visual-only, including through AI edits, tab switches and reloads.
- Generation reuses the configured server-side OpenAI provider/model. Per-type structured schemas restrict permitted shapes and relationships, followed by strict reference/notation validation. Recoverable failures have bounded retries; unsupported structured output falls back to validated JSON using the same model. Explain uses the actual graph. No generated code is executed.
- AI edits propose typed incremental operations. Review and explicitly apply them; revision and canvas-content checks reject stale previews. Semantic application is atomic and canvas edits form an undoable transaction. Local changes never propagate silently to other tabs; canonical entity name conflicts are rejected, while behavioral states/actions may refer to an owning entity. A locally renamed representation detaches its canonical-name reference.
- Autosave stores changed projects with optimistic revision checks. Ownership is checked on every document operation. History retains the latest **50** saves; restore creates a new revision. Conflict recovery allows duplication of a local draft or explicit reload. Compressed project/history updates are atomic on standalone MongoDB.
- **Export** supports PNG/SVG of the current page and JSON of the entire workspace. Class diagrams also support semantic Mermaid/PlantUML; other types report the format limitation. **Export all** creates a ZIP with project JSON and each diagram's PNG/SVG/JSON using an independent hidden editor, preserving the visible canvas and its history.

Shift-click two components, then **Connect selected**; first selection is the source. Connection type, endpoints, labels, multiplicities, events/guards, sequence order and fragment references are edited in Properties. Canvas shortcuts include Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, copy/paste, duplicate and delete; grouping and shortcut reference are in the tldraw menu.

## Files and integration

New module sources:

- `backend/packages/ai-design-studio/src/{schema,workspace,layout,operations,export,index}.ts`: strict shared contracts, graph integrity, atomic operations, semantic UML exports.
- `backend/api/src/ai-design-studio/{auth,ai,persistence,router}.ts`: studio-only authentication, rate limiting, existing-provider AI integration, MongoDB persistence and API.
- `frontend/web/src/ai-design-studio/{Studio,Properties,shapes,ExportAll}.tsx`, `canvas.ts`, `api.ts`, `studio.css`: canvas adapters, custom shape renderers, editors, assistant, exports and UI.
- Semantic unit tests, API/AI integration tests, Playwright workflows, studio TypeScript/ESLint configuration and setup/migration/live verification scripts.

Existing source changes are only the route import/registration in `frontend/web/src/App.tsx`, a navigation entry in `frontend/web/src/components/Layout.tsx`, and router/config registration in `backend/api/src/index.ts`. Package manifests/lockfile register dependencies; root predev/prebuild scripts compile the new shared module first. `.gitignore` protects the private studio configuration and test artifacts. `ai-design-studio-isolation.baseline.json` records pre-change source hashes.

This update adds `fflate` for ZIP exports and explicitly uses ELK in the shared package. Added runtime dependencies: `tldraw` 5.5.2, `elkjs` 0.11.1, `zod-to-json-schema`, and the new shared workspace package. Zod is reused and made explicit where needed. Added test/lint dependencies: Playwright, mongodb-memory-server, ESLint and typescript-eslint. React remains 18.3.1; React Flow remains installed.

MongoDB migration: `scripts/ai-design-studio-migrate.ts` creates only `ai_design_studio_designs`, a unique `designId` index and an owner/updatedAt index. It does not alter existing collections. No existing database model is overwritten.

The API integration tests use a temporary isolated MongoDB process; they do not touch the application's database. They use an installed `mongod` binary on this machine, or mongodb-memory-server's download elsewhere. Browser tests use Chrome and the generated local studio credentials. They create test designs under that account. Live tests make billable OpenAI requests. The browser tests mock AI responses for deterministic UI checks; real model generation and preservation are tested separately by the live script. The development-only `?studio-test=1` parameter exposes an editor test handle; it is absent in production builds.

## Limits and deployment blockers

- **The repository-wide build/typecheck already failed before this feature** in `backend/api/src/db/models/reactflow-architecture.model.ts`, lines 23–24, due to the Mongoose Mixed-array type definitions. That protected file remains untouched. Studio TypeScript checks and the frontend production build pass independently. Full application acceptance remains blocked by those existing errors.
- **Repository-wide lint is not configured**: the existing API lint command has no default ESLint configuration. Studio-specific lint passes using the separate configuration. No unrelated lint configuration was rewritten.
- **No tldraw production license was available in the workspace.** Development works, but production canvas deployment requires `VITE_TLDRAW_LICENSE_KEY`. License enforcement has not been bypassed.
- The new isolated login has no signup, password-reset or account-management UI; accounts are configured by the server administrator. It does not introduce another authentication provider or alter existing endpoints. Real-time collaboration/shared access is not implemented.
- A document snapshot is limited to 7 MB uncompressed. Retained compressed history is limited to approximately 14 MB to stay below MongoDB's document limit; if full, duplicate the design to begin a new history. Large uploaded bitmap assets can exhaust this limit.
- History retains 50 revisions. Export JSON for archival. Canvas snapshots contain all pages; PNG/SVG export the current page. Semantic text exports include all structured UML elements across pages.
- Automatic layout rejects detected collisions rather than silently rendering them. Manually overlapping shapes can prevent automatic routing; move the obstructing shapes or run Auto layout. Orthogonal bend/crossing costs minimize crossings but do not promise the globally optimal crossing count. Native freehand arrows are separate visual drawings.
- Workspaces hold up to 35 tabs. Undo/redo operates in the current mounted tab; saved version history restores the complete project across tab switches. Multi-diagram generation is bounded by provider output/context limits; large systems should be generated in smaller diagrams.
- The studio is lazy-loaded but its SDK/layout bundle is large; Vite reports a chunk-size warning. Responsive panels can be toggled, and small-screen editing benefits from hiding the assistant panel.

See `VERIFICATION.md` for observed results. A fully production-ready deployment cannot be claimed until the protected pre-existing build errors are resolved and a production license is configured.
